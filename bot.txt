  一、整体架构

1.1 文件结构
  main.py                      — 主插件类 MyPlugin(Star)，注册所有命令和事件处理器
  qqadmin/__init__.py          — 统一导出所有子模块的 API
  qqadmin/group_config.py      — 分群配置管理（核心配置读写）
  qqadmin/reply.py             — 自定义关键词回复
  qqadmin/mute.py              — 禁言系统
  qqadmin/kick.py              — 踢出系统
  qqadmin/blacklist.py         — 黑名单系统（分群+全局）
  qqadmin/audit.py             — 入群审核系统
  qqadmin/welcome.py           — 入群欢迎/欢送
  qqadmin/recall.py            — 消息撤回系统（含自身撤回）
  qqadmin/stats.py             — 统计/签到/积分系统
  qqadmin/timed_message.py     — 定时消息系统
  qqadmin/sub_admin.py         — 分群管理员
  qqadmin/player_reply.py      — 用户专属回复
  qqadmin/text_to_image.py     — 文转图
  qqadmin/api_client.py        — API 客户端封装
  scum/                         — SCUM 玩家数据校验、签到和游戏数据库工具
  auth.py / auth/manager.py   — 授权/卡密系统

1.2 配置体系
  全局配置文件: data/config/astrbot_plugin_joker_config.json
  分群配置目录: data/plugin_data/qqadmin/group_configs/{群号}.json
  授权数据文件: data/plugin_data/astrbot_plugin_joker/auth_data.json
  数据存储: JSON 文件 + 内存缓存（带 mtime 校验的缓存机制）

1.3 核心类
  MyPlugin(Star) — 继承 AstrBot Star 插件基类
  · 初始化时加载配置、创建定时任务
  · 维护功能开关缓存 _feature_cache（5秒 TTL）
  · 维护黑名单用户去重 _blacklist_kicked_users
  · 维护自身撤回任务集合 _recall_tasks
  · 维护授权到期提醒记录 _auth_reminder_sent

================================================================================
  二、核心数据流向（消息处理管道）
================================================================================

一条群消息到达后的处理顺序（按优先级从高到低）:

  ┌─────────────────────────────────────────────────────────────────┐
  │ 1. intercept_and_recall_bot_message (priority=999)              │
  │    @filter.on_decorating_result                                │
  │    拦截机器人自身发送的消息，安排 90 秒后自动撤回                 │
  │    条件: is_self_recall_enabled(群) == True                     │
  ├─────────────────────────────────────────────────────────────────┤
  │ 2. on_decorating_result (priority=默认)                         │
  │    文转图: 将文本消息转换为图片发送                              │
  │    条件: text_to_image_enabled && 非关机群                       │
  ├─────────────────────────────────────────────────────────────────┤
  │ 3. handle_group_request_auto_audit                              │
  │    @filter.event_message_type(GROUP_REQUEST)                    │
  │    处理加群请求，执行入群审核                                    │
  ├─────────────────────────────────────────────────────────────────┤
  │ 4. handle_module_help_commands                                  │
  │    @filter.event_message_type(GROUP_MESSAGE)                    │
  │    模块帮助路由: /定时消息、/黑名单系统 等触发帮助文本             │
  │    含: 入群邀请/审批通过通知事件处理                             │
  ├─────────────────────────────────────────────────────────────────┤
  │ 5. handle_direct_verification                                   │
  │    @filter.event_message_type(GROUP_MESSAGE)                    │
  │    直接（非命令格式）的验证回答处理                              │
  ├─────────────────────────────────────────────────────────────────┤
  │ 6. handle_message                                               │
  │    @filter.event_message_type(GROUP_MESSAGE)                    │
  │    主命令处理器                                                  │
  │    流程: 授权检查 → 开关机检查 → 命令预处理 → 自定义回复 →       │
  │          用户专属回复                                            │
  ├─────────────────────────────────────────────────────────────────┤
  │ 7. handle_auto_reply                                            │
  │    @filter.event_message_type(GROUP_MESSAGE)                    │
  │    自动回复处理（关键词匹配、冷却检查）                          │
  │    含: 关键词过滤检查（软门，不受开关机限制）                     │
  │    流程: 硬门(授权) → 关键词过滤 → 软门(开关机) → 功能开关检查    │
  │          → 关键词匹配 → 冷却检查 → 发送回复                      │
  └─────────────────────────────────────────────────────────────────┘

  消息前置过滤层:
  · _is_auth_command(): 授权命令直接放行，跳过硬门
  · _is_power_command(): 开关机命令在关机时仍可执行
  · _is_slash_prefix_allowed(): 检查分群是否允许斜杠前缀

  三、功能模块详解

3.1 SCUM 服务器查询
  ──────────────────────────────────────────────────────────────────
  功能: 查询 SCUM 生存游戏服务器在线人数、IP、版本、运行时间等
  数据源: Linux 网页 SCUM 查询中转
  核心类: LinuxScumQueryService(web_client/scum_query_service.py)

  实现步骤:
  1. 用户触发命令: /查询 (关键词/IP:端口)、/查询在线、/绑定id
  2. /绑定id: 保存服务器 ID 到 group_bindings.json
  3. /查询在线: Windows 将请求转发至 Linux 网页中转
  4. /查询: Linux 网页执行查询并将结果返回 Windows
     - 显示: 排名/ID/服务器名称/在线人数/IP地址/状态/地区/版本号/游戏时间
  5. 查询失败时不会回退到 Windows 本地数据源

  权限: read_only 模式下普通成员可查询，仅管理员可绑定/解绑
  配置: enable_query、enable_binding、permission_mode、query_relay_url

  联动:
  · 授权检查: 未授权群仅主人可使用
  · 开关机检查: 关机群禁用（主人豁免）
  · 自动轮询: 可配置每 N 秒自动刷新在线状态

3.2 授权系统
  ──────────────────────────────────────────────────────────────────
  功能: 卡密授权、分群授权管理、到期提醒、自动删除过期授权
  数据文件: auth_data.json (授权记录) + group_bindings.json (SCUM绑定)

  实现步骤:
  1. /激活授权 [卡密] → verify_license_key() → authorize_group(群号,到期时间)
  2. /查看授权 → get_group_auth_info() → 显示状态/到期时间/剩余天数
  3. /生成卡密 [天数] → generate_license_key() → 保存到 auth_data.json
  4. /增加时间 [天数] → add_auth_time() → 延长到期时间
  5. /取消授权 → deauthorize_group() → 删除授权记录
  6. 后台循环 _auth_expire_reminder_loop():
     - 每 {auth_expire_reminder_check_interval} 秒检查所有授权群
     - 计算剩余时间，≤ auth_expire_reminder_hours 时发送艾特群主提醒
     - 同一到期周期内距离上次发送 ≥ 配置间隔才重发
     - 自动删除: 超过 auto_delete_expired_auth_days 的过期群被清理

  关键机制:
  · 硬门 (Hard Gate): 未授权群的消息全部静默（除授权命令外）
  · 主人规则: 主人授权管理、卡密和网页同步控制命令不受开关机限制；普通业务/群管命令仍须先开机
  · 宽限期: 过期群保留 auto_delete_expired_auth_days 天后才真正删除
  · 永久授权: days=-1 → expire=-1 永不过期，不参与自动删除

  联动:
  · 几乎所有群管功能都依赖授权检查
  · 未授权群的 handle_message 直接 stop_event() 返回
  · 授权到期群的非授权命令对非主人用户完全屏蔽

3.3 入群审核系统
  ──────────────────────────────────────────────────────────────────
  功能: 加群审核、验证（数学/ID/审批码模式）、超时踢出
  数据: audit 存储在分群配置 + 内存 pending_verifications

  实现步骤:
  1. 收到加群请求 (GROUP_REQUEST 事件) → handle_group_request_auto_audit()
  2. 根据分群配置的 approval_mode 决定验证方式:
     - math: 生成随机数学题 → 等待用户回答
     - id: 显示 QQ 号码要求 → 用户输入正确 QQ 号
     - code: 生成审批码 → 等待管理员审批
     - 无/跳过: 直接放行
  3. 发送验证消息到群里，存储 challenge_id + request_data
  4. 用户输入答案 → handle_direct_verification() → verify_answer()
  5. 正确: approve_join_request() → 通过审核
     错误: 扣减尝试次数，超限则 reject_join_request()
  6. 超时检查: _verification_timeout_loop() 每 30 秒扫描
     - 超时则 kick_user_api() 踢出用户 + 撤回验证消息

  子功能:
  · 邀请统计: record_invitation() → 记录邀请关系
  · 过度邀请检测: check_excessive_invites() → 踢出异常邀请者
  · 审批通过通知: _process_group_join_notice() → 欢迎流程

  联动:
  · 审核通过 → 触发欢迎流程（自动/延迟发送欢迎语）
  · 审核通过 → 黑名单检测（全局+分群）
  · 审核超时 → 调用踢出系统 API
  · 邀请数据 → 统计系统（排行榜）

3.4 入群欢迎/欢送系统
  ──────────────────────────────────────────────────────────────────
  功能: 新成员入群欢迎语、退群欢送语、关键词触发欢迎、延迟发送
  数据: 存储在分群配置 features.welcome

  实现步骤:
  1. 审核通过或直接入群 → _process_group_join_notice()
  2. 检查全局黑名单 → 若命中则直接踢出（不触发欢迎）
  3. 检查分群黑名单 → 若命中则直接踢出
  4. 若启用审核: 发送验证消息（不触发欢迎）
  5. 若 auto_welcome=True:
     - 处理占位符: {user_name}, {time}, {group_id}
     - welcome_delay: 延迟 N 秒发送
     - 发送文本/图片欢迎消息
  6. 关键词触发: 用户发送 welcome_keywords 中的关键词时回复欢迎语
  7. 退群事件: farewell_enabled=True 时发送欢送语

  子功能:
  · 成员追踪: enable_member_tracking() 记录成员进出历史
  · 欢迎历史: log_welcome() → get_welcome_history() 供统计
  · 图片欢迎: add_welcome_image() → 图片列表轮播

  联动:
  · 依赖审核系统的审核通过事件
  · 黑名单在欢迎之前检测，优先级更高
  · 欢迎消息经过自身撤回系统（90秒自动撤回）

3.5 自定义关键词回复
  ──────────────────────────────────────────────────────────────────
  功能: 关键词自动回复，支持精确/模糊匹配、冷却、图片回复
  数据: 每个分群独立存储，格式 [{keyword, reply, type}]

  实现步骤:
  1. 收到群消息 → handle_auto_reply()
  2. 硬门: 授权检查 → 未授权静默
  3. 关键词过滤检查（软门，不受开关机限制）
  4. 软门: 开关机检查 → 关机群不回复
  5. 检查 reply 功能开关
  6. match_any_reply(群, 消息):
     - 遍历关键词列表
     - exact_match=True 精确匹配，否则模糊匹配
     - 返回匹配的关键词和回复数据
  7. 冷却检查: is_in_cooldown(群, 关键词, 用户ID)
     - 按用户+关键词维度冷却
     - 冷却时间内跳过回复
  8. 发送回复: 文本 or 图片链
  9. 图片回复: 下载远程图片保存本地 → chain.url_image() 发送

  子功能:
  · 随机回复: 同一关键词配置多个回复时随机选取
  · 冷却管理: set_cooldown / get_cooldown_remaining

  联动:
  · 关键词回复先于用户专属回复执行
  · 关键词过滤器在关键词回复之前触发
  · 回复消息经过自身撤回系统

3.6 用户专属回复
  ──────────────────────────────────────────────────────────────────
  功能: 对特定用户发送专属回复，艾特/不艾特模式
  数据: 分群存储，key=用户ID, value={messages, at_user}

  实现步骤:
  1. handle_message() 末尾检查
  2. 检查 player_reply 全局开关
  3. 检查分群 player_reply.enabled
  4. get_player_reply(群, 用户ID) → 获取用户专属配置
  5. 若启用且有消息列表 → get_random_message() 随机选取
  6. 根据 at_user 设置决定是否构建 At 消息链
  7. yield 发送

  联动:
  · 位于 handle_message 管道末尾，优先级低于关键词回复
  · 不经过冷却检查（可与关键词回复同时触发）

3.7 禁言系统
  ──────────────────────────────────────────────────────────────────
  功能: 禁言/解禁、定时解禁、全体禁言/解禁、自动禁言
  数据: 分群 mute 列表，格式 [{user_id, until, level, reason}]

  实现步骤:
  1. /禁言 @用户 [时长] [理由] → _parse_mute_command()
     - 解析 @mention 或 QQ 号
     - 时长支持数字(分钟)/10m/1h 等格式
     - 默认 5 分钟
  2. 权限检查: _check_feature_permission("mute", "use")
  3. 检查是否是管理员/群主（不能禁言上级）
  4. mute_user_api(群, 用户ID, 时长, 原因):
     - 计算绝对过期时间 until = now + duration
     - 调用 OneBot set_group_ban API
     - 写入分群 mute 列表
  5. 后台 _verification_timeout_loop() 也会触发禁言（关键词过滤触发）
  6. 定时解禁: 遍历 mute 列表，过期自动 unmute_user_api()

  子功能:
  · 定时全体禁言: /添加定时禁言 名称 cron
  · 定时全体解禁: /添加定时解禁 名称 cron
  · 自动禁言: 关键词过滤命中后自动执行

  联动:
  · 关键词过滤触发 → 自动禁言
  · 黑名单系统触发 → 自动踢出
  · 审核超时 → 自动踢出（经踢人系统）

3.8 踢出系统
  ──────────────────────────────────────────────────────────────────
  功能: 踢出违规用户、累计计数自动踢出/拉黑
  数据: 分群 kick 记录 [{user_id, count, last_time}]

  实现步骤:
  1. /踢出 @用户 [次数] → 权限检查
  2. add_kick_record(群, 用户ID): 累计踢人次数
  3. kick_user_api(群, 用户ID): 调用 OneBot set_group_kick API
  4. should_auto_ban(): 超过 kick_limit 次 → 自动加入黑名单
  5. 踢出后可选自动拉黑 (auto_blacklist_on_kick=True)

  子功能:
  · 批量踢出: 支持多人同时踢出
  · 踢出历史: get_kick_records() 查看记录

  联动:
  · 黑名单系统踢出 → 走踢人 API
  · 审核超时踢出 → 调用 kick_user_api()
  · 关键词过滤触发 → 可配置踢出
  · 自动踢人后可触发自动拉黑

3.9 黑名单系统
  ──────────────────────────────────────────────────────────────────
  功能: 分群黑名单（单个群）+ 全局黑名单（所有群）
  数据: 分群配置 blacklist 字段 + 全局 global_blacklist 字段

  实现步骤:
  1. /拉黑 @用户 [天数] [理由] → 解析参数
     - 天数=0或省略 → 永久拉黑
     - 天数>0 → 计算过期时间
  2. 踢出群内存在的黑名单用户 (set_group_kick)
  3. 若用户不在群内 → 仅记录黑名单，跳过踢出（记录日志）
  4. add_to_blacklist(群, 用户ID, 过期时间, 原因)
  5. auto_kick=True → 入群时自动踢出
  6. 过期黑名单: 后台定时检查过期黑名单并自动解除

  子功能:
  · /删黑: 删除黑名单
  · /查看黑名单: 显示分群+全局黑名单
  · /全局拉黑: 跨所有群拉黑

  联动:
  · 入群检测 → 黑名单命中自动踢出
  · 踢出系统 → 可配置踢出后自动拉黑
  · 审核失败 → 可配置自动拉黑 (auto_blacklist_on_verify_fail)
  · 关键词过滤 → 可配置踢出/拉黑
  · 黑名单用户的命令全部屏蔽（包括主人命令在过期群）

3.10 关键词过滤系统
  ──────────────────────────────────────────────────────────────────
  功能: 敏感关键词检测、正则匹配、自动警告/禁言/踢出
  数据: 分群 feature 配置 + 自定义关键词/正则列表

  实现步骤:
  1. handle_auto_reply() 调用 _check_keyword_filter(event)
  2. 检查功能开关: 分群 → 全局
  3. 管理员跳过 (admin_bypass_filter=True)
  4. 合并关键词: 默认关键词 + 自定义关键词（去重）
  5. 合并正则: 默认正则 + 自定义正则（去重）
  6. 文本匹配: for 关键词 in 列表 → `if 关键词 in message`
  7. 正则匹配: for 正则 in 列表 → re.search(正则, message)
  8. 命中后执行 _handle_filter_action(event, 关键词):
     - warn: 发送警告消息 + 可选禁言
     - mute: 禁言 filter_mute_duration 秒
     - kick: 踢出
     - blacklist: 加入黑名单
  9. 返回 True 表示已处理，停止事件传播

  子功能:
  · /添加敏感词 关键词 → 全局添加
  · /删除敏感词 关键词 → 全局删除
  · /查看敏感词 → 查看所有（全局+分群）

  联动:
  · 在关键词回复之前检查（软门，不受开关机限制）
  · 命中后触发禁言/踢出/拉黑等连锁反应
  · 关键词过滤先于关键词回复执行

3.11 消息撤回系统
  ──────────────────────────────────────────────────────────────────
  功能: 违规关键词撤回 + 自身消息定时撤回（90秒）
  数据: 分群 recall 配置

  实现步骤 — 违规撤回:
  1. 后台消息监听 → is_recall_enabled(群)
  2. should_recall_message(群, 消息):
     - 关键词匹配: recall_keywords 列表
     - 正则匹配: recall_regex 列表
     - 艾特全体: 检测 @all
     - 链接检测: 检测 URL
     - 敏感词检测: 检测违规内容
  3. 命中后: bot.delete_msg(message_id) 撤回
  4. 可选通知: recall_notification=True → 发送警告

  实现步骤 — 自身撤回:
  1. on_decorating_result(priority=999) → intercept_and_recall_bot_message()
  2. 检查 is_self_recall_enabled(群)
  3. 清空原始 result.chain，重新构建消息链
  4. 通过 call_action(send_group_msg) 直接发送（绕过框架的 send）
  5. 获取新的 message_id
  6. _recall_bot_message(bot, message_id, recall_time) → asyncio.sleep(90) → delete_msg

  子功能:
  · /开启撤回: 开关撤回功能
  · /设置撤回时间: 5-300 秒
  · /添加撤回关键词: 关键词撤回
  · /添加撤回正则: 正则撤回

  联动:
  · 所有机器人发出的消息（定时消息/授权提醒/欢迎等）均经过自身撤回
  · 定时消息可通过 auto_recall=False 跳过自身撤回
  · 授权到期提醒 auto_recall=False（避免撤回提醒消息）

3.12 定时消息系统
  ──────────────────────────────────────────────────────────────────
  功能: Cron 表达式定时发送消息、定时全体禁言/解禁
  数据: 分群 timed_messages 列表

  实现步骤:
  1. /添加定时消息 名称 cron 内容 → 添加到 timed_messages
  2. /添加定时禁言 名称 cron → 添加定时全体禁言
  3. /添加定时解禁 名称 cron → 添加定时全体解禁
  4. 后台 _timed_message_loop():
     - 每 60 秒执行 _send_timed_messages()
     - 加锁防止并发执行 (_sending_timed_messages 标志)
     - 遍历所有群 → 检查功能开关 → get_due_messages(群)
  5. get_due_messages(): 解析 cron 表达式，返回到期任务
  6. 执行任务:
     - message 类型: _send_group_msg(群, 内容)
     - whole_ban 类型: set_group_whole_ban(群, enable=True)
     - whole_unban 类型: set_group_whole_ban(群, enable=False)
  7. mark_sent(): 标记已发送，更新 last_sent_at

  子功能:
  · /查看定时消息: 列出所有定时任务
  · /删除定时消息: 按序号或名称删除
  · /清空定时消息: 清空全部

  联动:
  · 定时消息发送经过自身撤回系统（auto_recall 可配置）
  · 依赖分群配置的定时消息 enabled 开关
  · 全体禁言/解禁走 OneBot API

3.13 统计/签到系统
  ──────────────────────────────────────────────────────────────────
  功能: 签到积分、排行榜、个人信息、邀请统计
  数据: 分群 stats 配置 + 用户积分数据

  实现步骤:
  1. /签到 → signin(群, 用户ID):
     - 检查冷却时间 (cooldown=0 表示不限制)
     - 计算积分 (base_points + 随机加分)
     - 写入积分表
  2. /排行榜 → get_ranking(群): 按积分排序
  3. /我的信息 → get_user_info(群, 用户ID): 显示积分/签到天数
  4. /群统计 → get_group_stats(群): 邀请统计/活跃度

  子功能:
  · 邀请排行: 结合审核系统的邀请数据
  · 积分榜: add_points / deduct_points 操作

  联动:
  · 审核系统提供邀请数据
  · 欢迎系统的历史数据参与统计
  · 积分可被其他功能（如抽奖）消费

3.14 分群管理员
  ──────────────────────────────────────────────────────────────────
  功能: 主人指定群内管理员，管理特定功能（黑名单/禁言等）
  数据: 分群 sub_admin 列表 [{user_id, permissions: []}]

  实现步骤:
  1. /添加分群管理员 @用户 → 仅主人可执行
  2. 设置权限: set_sub_admin_permissions()
     - 可选权限: blacklist, mute, kick, audit 等
  3. /查看分群管理员 → 列出所有子管理员及其权限
  4. 权限检查: has_permission(用户ID, 功能名)
     - 优先检查主人群主权限
     - 然后检查子管理员权限列表

  联动:
  · 子管理员权限低于群主/主人
  · 子管理员可管理但不拥有群主级权限
  · 权限粒度细到每个功能

3.15 文转图系统
  ──────────────────────────────────────────────────────────────────
  功能: 将文本消息自动转换为图片发送
  数据: 分群 text_to_image 配置（字体/颜色/间距等）

  实现步骤:
  1. on_decorating_result(priority=默认) → _should_convert_to_image(event)
     - 检查功能开关（分群+全局）
     - 检查关机状态（主人豁免）
  2. 从 result.chain 提取所有 Plain 组件的文本
  3. 调用 text_to_image(文本, 字体大小, 颜色, 背景, 行距, 边距)
     - 使用 PIL/Pillow 绘制图片
     - 支持中英文混排
  4. 替换 result.chain = [Image(file=图片路径)]
  5. after_message_sent(): 发送完成后删除临时图片文件

  子功能:
  · /开启文转图、/关闭文转图
  · 分群自定义: font_size, font_color, bg_color, line_spacing, padding

  联动:
  · 与自身撤回系统独立（文转图在拦截之前执行）
  · 文转图后的消息仍是机器人消息，会被自身撤回

3.16 分群配置管理
  ──────────────────────────────────────────────────────────────────
  功能: 分群独立配置管理、全局配置自动同步、配置导入导出
  数据: 每个分群一个 JSON 配置文件

  实现步骤:
  1. /分群设置 → show_group_config_help():
     - 显示当前分群所有功能的启用状态
     - 显示 power_status (开机/关机/未设置)
     - 显示 SCUM 绑定状态
  2. /开启/关闭 [功能] → set_feature_enabled(群, 功能, True/False)
  3. 自动同步: _periodic_config_sync() 每 5 秒检查
     - 检测全局配置文件 mtime 变化
     - 变化时 clone_global_config_to_group() 同步到所有已授权群
  4. 配置文件路径: data/plugin_data/qqadmin/group_configs/{群号}.json

  子功能:
  · /克隆配置 [源群]: 从其他群克隆配置
  · /重置群配置: 恢复默认
  · 导出/导入: JSON 格式配置迁移

  联动:
  · 几乎所有功能的开关都通过分群配置控制
  · 配置变化实时生效（带 mtime 校验缓存）
  · 自动同步确保全局配置变更下发到所有群

================================================================================
  五、关键机制说明
================================================================================

5.1 双门检查机制
  · 硬门 (Hard Gate): 授权检查
    - 未授权群 → 所有消息静默（除授权命令、主人命令）
    - 实现: _check_group_authorized() → handle_message 中 stop_event()
  · 软门 (Soft Gate): 开关机检查
    - 关机群 → 不回复消息（关键词过滤除外，用于监听类功能）
    - 实现: _is_group_powered_on()

5.2 权限等级体系
  owner > admin > member
  · 主人: owner_ids 配置的 QQ 号
  · 群管理员/群主: event.role 或 get_group_member_info()
  · 普通成员: 其他用户
  · 子管理员: owner 指定，按功能授权

5.3 消息发送层级
  · yield self._yield_plain(event, 文本) → 框架自动发送
  · yield self._yield_chain(event, 链) → 框架自动发送
  · await self._send_plain(event, 文本) → 框架发送 + 手动日志
  · _send_group_msg(群, 消息) → 直接 call_action(含自身撤回)
  · _send_group_msg_with_id(群, 链) → 直接发送 + 返回 message_id

5.4 自身撤回流程
  1. 机器人发送消息
  2. on_decorating_result(priority=999) 拦截
  3. 清空框架消息链 → 重新通过 call_action 发送
  4. 获取 message_id
  5. asyncio.create_task(recall_bot_message)
  6. 90 秒后 bot.delete_msg(message_id)
  7. 日志: 拦截→发送成功→安排撤回→实际撤回

5.5 缓存机制
  · _config_cache: 分群配置文件 mtime 缓存（避免频繁读盘）
  · _feature_cache: 功能开关状态缓存（5秒 TTL，同一条消息内复用）
  · _auth_reminder_sent: 授权到期提醒去重记录
  · _recall_tasks: 自身撤回 asyncio.Task 集合
  · _group_member_role_cache: 群成员角色缓存（5分钟 TTL）
  · _group_owner_cache: 群主 QQ 缓存（5分钟 TTL）

5.6 并发保护
  · _sending_timed_messages: 定时消息发送加锁
  · _verification_check_running: 验证超时检查加锁
  · _recently_kicked: 验证超时踢出去重（5分钟 TTL）
  · _blacklist_kicked_users: 黑名单踢出去重
  · _recall_tasks: 撤回任务集合（plugin.terminate() 时统一取消）

5.7 热重载保护
  · initialize() 取消旧任务: _timed_message_task, _verification_timeout_task,
    _auth_expire_reminder_task
  · 扫描所有遗留的 _timed_message_loop 等协程任务并取消
  · terminate() 取消所有 _recall_tasks
  · 防止热重载后旧代码的定时任务继续运行

5.8 命令拦截优先级
  按 AstrBot 框架注册顺序:
  1. @filter.on_decorating_result(priority=999) — 自身撤回
  2. @filter.on_decorating_result — 文转图
  3. @filter.event_message_type(GROUP_REQUEST) — 审核请求
  4. @filter.event_message_type(GROUP_MESSAGE) — 模块帮助
  5. @filter.event_message_type(GROUP_MESSAGE) — 直接验证回答
  6. @filter.event_message_type(GROUP_MESSAGE) — handle_message
  7. @filter.event_message_type(GROUP_MESSAGE) — handle_auto_reply
  8. @filter.command(...) — 具体命令处理器（AstrBot 自动匹配）
