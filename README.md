# Joker插件 - SCUM查询与QQ群管

本次双端更新版本：`1.11.405`；完整变更见 [CHANGELOG.md](CHANGELOG.md)。

当前插件发布版本：`1.11.405`。

集SCUM服务器查询与QQ群管功能于一体的多功能插件。

网页与 Windows 双端共用发布版本：`1.11.405`。Linux 网页负责分群配置、SCUM 外部查询、游戏插件 WebSocket 链接、音乐名片签名服务、执行端开关和连接检测；Windows 插件主动同步并执行群操作，SCUM 查询只转发到 Linux 处理。SCUM 查询实现位于 Linux 包的独立 `web_client/scum_provider.py`，不会再导入 Windows 的 AstrBot 或 `scum` 模块；SCUM 服务器搜索和 ID 详情只通过配置好的中转站查询。管理员后台只配置小程序网站和实际游戏插件链接，Linux-Windows 内部入口会自动生成；用户端先验证主人发放的 `JG...` 游戏心跳卡，再输入该网站发放的 32 位十六进制 WebSocket 卡密。用户卡密只有在 im3 返回明确授权字段时才会加密保存，仅确认 `join_room` 而没有授权回执会验证失败且不会保存。点歌按分群默认平台单独搜索，QQ/网易云优先使用 astr_meting_music 兼容的 GET 签名名片；QQ 签名失败时不再回退到会触发“发送者版本过低”的原生名片，网易云仍保留平台原生回退，其他平台不会发送伪音乐卡片。Steam 游戏签到会在远程 FTP 数据库写入并回传确认后才返回成功，写入失败会返回失败原因；快照未就绪时签到前会尝试补拉当前服务器数据库，并显示明确失败阶段。FTP 与数据库只在目标分群的“游戏服务器”中设置：一台服务器统一维护 FTP、远程 SQLite、SCUM ID 和游戏 WebSocket；不同群、不同服务器均不共享凭据、远程路径、活动状态或快照。Windows 只使用按群号和服务器编号自动生成、同步后自动回传的临时快照，未生成快照时不会写入本地默认数据库。数据库快照访问失败会明确提示游戏卡密心跳、群管授权和网页快照状态。群称号和群名片操作由 NapCat 执行端确认成功后才会写入规则；称号操作会使用实际处理当前群消息的 QQ 账号，避免多账号环境中的群主误判；若 packetBackend 不可用，会提示检查 NapCat 的 PacketBackend 初始化。Linux 更新包会兼容旧版安全接收器，并在拒绝时明确列出缺失文件。版本安装与更新状态全部按中国标准时间显示。FTP 配置新增“保存并检测 FTP”，测试结果显示当前服务器档案；数据库测试结果显示实际选中的远程数据库路径，避免检测旧配置或误用其他服务器数据库。群成员目录会先保存在 Windows 本地，Linux 网页短暂 502 或超时时不会覆盖已有成员；网页恢复后，Windows 会自动补传尚未确认的成员目录。成员刷新会遍历 AstrBot 当前加载的全部 QQ 客户端，优先使用实际返回完整成员目录的客户端；小群收到完整新快照后会清理 Linux 端已退群的旧成员；入群事件会新增成员，退群事件会删除成员并立即进入网页补传队列。登录页可直接登记群聊授权卡密，首次登记自动初始化默认群聊功能；群配置可强制 SteamID 验证并自定义未验证发言禁言时长；网页点击刷新成员列表时只接受 Windows 实时成员接口，不再用旧缓存冒充新数据。SteamID 入群验证和绑定提示只通过私聊发送，群内验证命令会自动撤回且不会公开答案；入退群通知会延迟触发 Windows 实时成员刷新；网页重复禁言请求会去重并先选择当前群的群主/管理员机器人；实时接口只返回部分成员时不再把旧成员拼回目录，刷新失败或缺少实时面板时会清空不可确认的成员目录，等待下一次成功通联；全局黑名单允许操作只为当前群创建例外，删除本群黑名单记录会真正移除本群记录；消息接口缺少 message_seq 时保留 message_id，避免同一秒不同消息被错误合并；入群、退群、禁言、解除禁言和踢出记录会即时同步并按新到旧显示；修复远程运行时摘要解析失败导致的黑名单和群管记录空白，Linux 端按时间从新到旧显示全局/本群黑名单及审核、禁言、踢出、拉黑记录。Linux 网页保存群名片前缀时会同步 Windows 兼容字段，并立即排队应用现有成员；清空前缀会移除旧前缀，新成员继续按最新规则执行。

游戏验证现在分成两张独立卡：主人生成的 `JG...` 卡密只负责本群游戏心跳授权；小程序/WebSocket 网站发放的实际卡密由用户在群详情页输入，网页会先向后台配置的网站发送 `join_room` 验证，并要求网站明确返回授权结果。只有 JG 心跳有效、用户网站卡明确验证成功且 Windows 确认游戏插件 `/ping` 成功后，游戏指令和奖励才会执行。

部署和代码边界请先查看 [PROJECT_STRUCTURE.md](PROJECT_STRUCTURE.md)。其中说明了
Windows 执行端、Linux 网页端、同步数据流和发布包禁止包含的敏感文件。

### 首次部署默认配置

从 Git 仓库复制插件到新的 AstrBot/NapCat 服务器后，直接启动 AstrBot 即可。插件发现
`data/config/astrbot_plugin_joker_config.json` 不存在或为空时，会根据 `_conf_schema.json`
自动生成一份默认配置并保存；已有配置不会被覆盖。群组配置、授权数据和运行记录仍会在
实际使用时写入 `data/plugin_data/`，不会随 Git 仓库上传。

| `/开启定时消息` / `/关闭定时消息` | 开关本群定时消息功能 |

Cron 使用五段格式：`分 时 日 月 周`。本插件中星期为 `0=周一`、`6=周日`，五段条件需要同时满足；支持 `*`（任意）、`*/15`（每 15 分钟）、`0-4`（范围）和 `0,2,4`（列表）。

```text
# 每天 09:00 发送消息
/添加定时消息 早安 0 9 * * * 大家早上好！

# 周一至周五 18:30 发送消息
/添加定时消息 工作日提醒 30 18 * * 0-4 该下班啦！

# 每天 23:00 全体禁言，07:00 解禁
/添加定时禁言 夜间禁言 0 23 * * *
/添加定时解禁 早间解禁 0 7 * * *
```

- Linux 网页端也可为当前分群上传图片自动回复：图片存放在服务器数据库，配置仅同步资源 ID 与哈希，Windows 使用已绑定的 HTTPS 同步地址主动下载和本地缓存，不依赖固定域名或 Windows 公网端口。

## 💾 数据存储

### 客户网页后台

插件附带 `web_client` 客户中心。推荐架构是“本地 AstrBot 主控 + 服务器网页调取数据”：本地插件主动通过 HTTPS 上传脱敏配置并拉取网页改动，不需要服务器访问本机。客户通过邮箱验证码注册账号，再在登录后登记已激活的群卡密；续费换卡不影响账号。网页支持 MySQL、多用户分群管理、开关机、功能配置、Cron 定时任务、自动回复、后台 SMTP 邮箱配置，以及每个分群独立维护的 FTP/FTPS 和 FTP 数据库文件选择。安装与部署步骤见 [`web_client/README.md`](web_client/README.md)。

客户进入目标群后，在“服务器与数据库”先建立独立 FTP 连接，再创建服务器档案并选择连接和 SQLite 数据库文件；每个分群最多可建立 32 条 FTP 连接与 32 个服务器档案。
配置按用户和群号保存于 Linux 网页数据库的 `portal_settings.external_integrations:user:<用户ID>` 文档（`ftp_connections[群号][FTP连接ID]` 与 `profiles[群号][服务器档案ID]`），
与网页自身的 `JOKER_WEB_DATABASE_URL` 完全分离。密码使用会话密钥派生的 Fernet 密文保存，
不会同步到 Windows、写入日志或进入部署包；Windows 只接收脱敏的服务器标识与自动生成的分群快照位置。SQLite 文件由网页从所选 FTP 档案临时下载并校验，
同步到 Windows 后再进行签到或奖励写入；写入成功必须回传同一 FTP 档案才会回复成功。无需也不能手工配置或使用插件自带的本地数据库。

#### 绑定 Linux 网页配置中心

在 AstrBot 插件设置的“绑定 Linux 网页配置中心”中启用绑定，填写反向代理后的 HTTPS 网页域名、Linux 服务器中的 `JOKER_WEB_SYNC_TOKEN` 和 `JOKER_WEB_CARD_PEPPER`，保存后等待本机机器人自动同步。网页不需要也不能通过 SSH 连接 Windows；SSH IP、端口、root 用户和密码都不属于插件配置，不能填写或保存到这里。

- 使用 `/网页绑定状态` 查看是否已启用、配置是否完整、最近一次同步和安全错误码。
- 使用 `/测试网页连接` 做一次只读连接测试；它会校验网页地址、同步令牌和 Card Pepper，但不会上传或修改任何分群配置。
- 两个令牌必须分开：Linux `.env` 的 `JOKER_WEB_SYNC_TOKEN` 只与 Windows `web_sync.sync_token` 相同，用于 HTTPS 网页同步；管理员在 `/admin/websocket` 生成的“游戏 WebSocket 入口令牌”会随认证同步写入 Windows `web_sync.game_websocket_token`，只用于连接 `/api/sync/v1/ws` 和游戏调用。两者不能填写成同一值，也不要把游戏入口令牌手填进 Windows。
- 游戏插件 WebSocket 的实际连接在 Linux 网页配置：分群配置的“游戏服务器”档案优先，全局回退在 `/admin/websocket` 的“默认游戏插件 WebSocket”中设置。API Key 在 Linux 数据库加密保存，通过已认证同步下发；Windows 只保存运行投影并按文档连接 `ws(s)://主机:端口/ws?apiKey=...`。多台 SCUM 服务器分别填写不同档案，多台 Windows 电脑各自运行插件并使用不同的持久客户端 ID，网页后台的最大执行端数量需覆盖在线电脑数。
- 也可以直接在 Linux 网页的“分群配置 → 工具与扩展 → 游戏服务器”中维护本群的多条插件 WebSocket 档案。每台服务器使用完整文档链接，网页保存后随该群配置通过 HTTPS 同步到 Windows；本群档案优先于全局 Windows 档案，停用本群档案时不会误发到其他服务器。
- im3 使用文档规定的 Socket.IO `join_room` 通道，后台管理员只填写网站地址、路径和 `bot_main` 或 `bot_child_<guid>` 身份；用户在分群页面输入网站发放的实际卡密后验证。签到奖励成功后才写入签到记录，插件 WebSocket 未确认执行结果不会消耗签到次数。
- 后台心跳默认不在 Windows 群聊 CMD 重复显示“网页通联失败/恢复”；失败仍按限频策略写入插件日志，网页状态页也会更新。需要排查时，在插件设置中开启“Windows CMD 显示网页通联状态”。
- 网页通联按网页登录账号绑定的群划分范围：启动首轮只协商范围，只有已绑定群持续上传配置、运行摘要、消息记录并接收网页修改；未绑定群仅保留首次卡密登记所需的脱敏授权握手，不上传完整群配置。
- 这两个命令仅机器人主人可用，且和授权管理命令一样不受当前群开关机状态限制。

- 网页不会上传群消息、签到历史、邀请统计、黑名单记录、原始卡密、授权密钥或主人账号。
- 网页“群消息收发记录”仅在管理员开启总开关且单独授权账号后显示。默认上传发送、撤回、审核、禁言等脱敏动作摘要；管理员可再明确开启消息正文同步，让已授权客户查看自己群的接收消息与机器人回复。图片链接、Windows 路径、卡密和私聊内容不会上传。
- 网页改动显示为“待同步”，本地机器人拉取并落盘后才正式生效。
- 网页或网络中断不会影响本地机器人继续按现有配置运行。
- 卡密生成/删除和全局插件设置始终由本地主人命令或本地 AstrBot 设置完成。
- 本地同时删除授权记录和群配置后，下次同步会清除服务器上的旧配置投影与卡密指纹，网页账号关系和审计日志仍保留。

- **分群配置**：每个群的独立配置和数据存储在 `plugin_data/qqadmin/group_configs/群号.json`
  - 包含：自定义回复、黑名单、禁言列表、签到、邀请统计、定时任务、操作日志、撤回记录等
  - 每个群使用各自的配置，互不影响
- **全局配置**：插件设置中的默认配置，用于克隆到分群
- **授权数据**：存储在 `plugin_data/auth/auth.json`
- **群组绑定**：存储在 `plugin_data/auth/bindings.json`

## ⚠️ 注意事项

1. 所有命令均支持带 `/` 和不带 `/` 两种方式
2. 卡密只能使用一次，重复使用会提示"该卡密已被使用过"
3. 主人账号在配置中添加，格式为纯数字ID
4. 建议修改默认的管理密钥以提高安全性
5. 分群配置独立存储，每个群使用各自的配置和数据
6. 修改全局配置后，需要使用 `/克隆全局` 同步到各群
7. 使用文转图功能需要安装 Pillow 库：`pip install pillow`

- `/自动回复` 统一为正式名称并兼容 `/自定义回复`；`/群设置` 统一为正式名称并兼容 `/分群设置`。
- 明确签到、状态、日历、签到排行、积分排行、我的信息和群统计均归属 `stats` 统计模块，同时保留原有直接执行入口。
- 完善分类帮助中的实时状态、权限、子命令、配置方法、Cron 示例及签到奖励说明。

### v1.7.0
- 新增本地主控、远程网页调取数据模式；支持出站主动同步，无需本机公网端口。
- 网页增加本地在线、离线和待同步状态，远程模式隔离群运行数据与敏感授权数据。
- 同步任务支持设置热更新，并能同步清理本地已经删除的授权/群配置投影。
- 修复关键词过滤 `delete` 动作未执行撤回、Cron 倒序范围误通过和审核模式选项不一致。
- 扩展签到数据接口、奖励配置、月历与排行，并完善定时消息 Cron 帮助。

### v1.6.0
- 新增自然日签到、签到状态、积分排行、个人信息和群统计命令。
- 新增 `/定时播报 HH:MM 内容` 和 `@全体` 广播格式，定时任务列表显示执行状态和最近执行时间。
- 邀请统计支持事件去重、按日统计、邀请状态汇总和成功入群排行。
- 群消息记录覆盖文本、图片、表情、@、回复、卡片等消息段摘要，并支持按用户查看撤回记录。
- 插件设置新增授权过期、开关机状态和撤回通知消息模板；所有模板仍受授权、白名单和开机门禁限制。

### v1.5.1
- 优化入群验证系统：
  - 修复尝试次数计数错误（第3/3次尝试时正确显示0次机会）
  - 验证超时时间实时显示剩余时间
  - 验证失败后立即踢出群聊
  - 验证成功消息简化为"验证成功！欢迎加入本群！"
- 解除禁言命令支持直接输入用户ID（`/解除禁言 @用户|用户ID`）
- 扩展消息缓存功能：
  - 缓存原始消息内容（包括图片CQ码）
  - 添加 `/查看撤回消息` 命令，管理员可查看已撤回的消息记录
  - 支持按用户筛选和数量限制
  - 新增消息缓存配置项（缓存保留天数、单用户最大缓存数等）
